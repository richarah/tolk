# DECISIONS

- Installer: `uv` creates `.venv` and installs the package. `pip` and `ensurepip` are missing on this machine. `uv` is not a runtime dependency.
- Parser session: one `delphin.ace.ACEParser` opened on first use and kept open in `tolk/erg.py`. The idea of keeping the session open comes from the description of SQUID in SPEC.md. SQUID's code was not read.
- Reading choice: only readings whose sentence index is bound by a non-`unknown` predicate are eligible (see PLAN.md item 9). Fixtures: "Every bird flies" and "Superman flies" have noun-reading parses that bind the index only through `unknown`.
- Fixture slugs: lowercase text with runs of non-alphanumerics replaced by `_`.
- Compound names: the head is `ARG1` and is last in the text, so the constant is `ARG2` + `_` + `ARG1`.
- Single home: slug and sentence list live in `tests/helpers.py`, imported by `scripts/record.py` and the tests. The user's update says each fact has one home.
- Mapping shape: `map_ep(ctx, ep)` per family module, called in fixed order from `compile.py`. No registry, because a dict of handlers would be the registry the spec forbids.
- Reading choice: only eventive readings compete (an EP takes the sentence index as ARG0 and is not `unknown`). Among non-refused candidates the one with the most predicates in the store wins, ties by parser order. If every eventive reading refuses, the first eventive reading's refusal is returned, not reading 0's, because reading 0 is often a noun parse.
- Restriction of a wh word: an abstract predicate (no leading underscore) under `which_q` gives no atom and is not named in code. The wanted variable is simply unrestricted.
- Copula: `_v_id` (the identity sense) is recognised by its suffix. An indefinite or universal complement is aliased to the subject, so it adds atoms to the subject and creates nothing. A named complement is refused `IDENTITY_NOT_YET` until phase 4.
- Unexpressed arguments: an i-variable mentioned by no other predication is dropped; a gap before an expressed argument is refused `ARGUMENT_GAP`.
- Rule shape: a universal at top level makes a rule. Its restriction (and the restrictions of quantifiers nested in it) is the body; everything else is the head. Head variables the body does not bind are created (printed with `!`).
- Lemma scan exemption: `every`, `no`, `do`, `does`, `is`, `a`, `an`, `the`, `be` come from determiner and auxiliary predicates. The scan ignores them. Quantifier names are allowed in rules by SPEC rule 3. The copula is recognised by its sense suffix, not its lemma.
- Ask mode: every indefinite and every wh variable is a variable. Events are variables. Tell mode: events and indefinites become fresh constants \`e1..\`, \`a1..\`.
- `Reading` gained `top` (the LTOP handle). It is needed to find the main clause.
- Store schema deviations: `rule` has two columns the spec does not list. `lf` holds the rule as JSON so the engine can run it again, and `ran` is the round in which the rule last ran (NULL before its first run). `why` has a unique index over `IFNULL(sentence, 0)` and `IFNULL(rule, 0)` because SQLite treats NULLs as distinct. The spec does not say so, but a unique row per premise set is what keeps a second run from adding why rows.
- Fresh constants: compile gives local ids `e1`, `a1`. The store renames each to an id no earlier sentence used, so `e1` in one sentence never means the same event as `e1` in another.
- Repeated statements: a sentence whose text is already stored adds no facts. Two sentences with different wording that mean the same thing still add facts, because each gets fresh events. Open: identity of events by content.
- Round semantics: told facts take round max+1. A rule's first run has no round constraint. Later runs require at least one body atom from the previous round, as the spec says. Stopping: a round that adds nothing ends the run.
- Skolem guard: a body binding whose value starts with `sk:<rule id>:` blocks the match, so a rule never reuses its own skolems.
- `tests/helpers.tell_text` tells one sentence through compile and store. It is test scaffolding and will be replaced by `Mind.tell` in phase 3, which removes it.
- Answers: solutions for a wh question are sorted by constant id, so "Kim and Tweety" is the stable order. The spec does not fix an order.
- Proof per body atom: a yes/no answer shows the first matching solution's proofs. A wh answer shows one proof set per solution.
- `say.fact_text` shows skolem ids raw (for example `sk:6:x8:rex`). A readable name would have to parse the skolem format, which lives in the engine. Left stiff on purpose.
- `Mind.hear` decides between tell and ask from the chosen reading's logical form. `tell` and `ask` are the same call, so a statement given as a question is answered, not stored.
- Engine ask queries use `Match` with no skolem guard and no delta, so the same generator serves rules and questions.
- Negative facts: the event column is empty (`''`). A stored negative verb is `not fly(pingu)` with `a0 = ''`, and a question's event variable matches it.
- Negated event in a rule head or told atom: `Const("", "empty")`, printed `_`. In a rule body it is a local variable, so negation as failure matches any event.
- Contradiction: telling a fact whose opposite is stored or derived is refused before anything is written, and the opposite's proof is shown. The opposite matches on predicate, polarity and non-event arguments.
- Conflict rows: a positive and a negative fact that clash get a conflict row once one of them is derived. Told-against-told clashes are refused, so they never reach the table.
- Identity: `Same(a, b)` keeps the older entity (lower rowid). The other's facts move onto it, a name row records the merge, and later mentions of the dropped name map to the kept one. A copula with a named complement and a non-name subject is refused `IDENTITY_NOT_YET`.
- Definites: a definite resolves to the one known thing with every restriction predicate (a positive fact). Zero or two-plus matches are refused `DEFINITE_MATCHES` with the count.
- "No X V": a top-level `_no_q` makes a universal rule whose head clause is negated. "No penguin flies" is `rule not fly(_, X) :- penguin(X)`.
- Unexpressed subject: an event predicate whose first non-event argument is unexpressed is refused `UNEXPRESSED_SUBJECT`. Reading 2 of "Is Sandy happy?" was otherwise stored as `happy(E)`, a silent drop.
- Unbound variable: a variable that no quantifier binds and that is not an event is refused `UNBOUND_VARIABLE`, instead of being ignored.
- Negation as failure is evaluated in rounds, so a negated predicate that an earlier round derives may be missed until the round that derives it. The spec's stratification check (no negated predicate depends on the rule's head) is enforced, but a full strata-by-strata evaluation is not built. Open.
- `choose` takes a `lookup`, and `compile_reading` uses it only for definites.
- Prepositions: `_in_p_loc(e9, e2, oslo)` becomes `in(e2, oslo)`. The preposition's own event argument is dropped, and its object attaches to the event it modifies.
- Where: `loc_nonsp` in a question becomes the pattern `_*_p_loc`. A star in a predicate means GLOB in SQL. The pattern matches any locative preposition by sense suffix, so "Where does Kim live?" finds `_in_p_loc`. A statement that uses `loc_nonsp` is refused, since a pattern cannot be stored.
- Tense: `tense(e, past)` only for a told past event. Its object is a constant of kind `value`, which is not an entity.
- Reading overlap counts (predicate, arity) pairs, not predicate names. The arity of a stored fact excludes the empty event column.
- Suppositions: one level only. Rules and identity merges are refused inside a supposition, because the store has no context on rules or merges and drop must remove exactly what the supposition added. Both are open items.
- Drop removes orphan fresh entities (kinds event, anon, skolem) that no remaining fact mentions.
- Definites inside a supposition see the world's things and the supposition's.
- Sentence identity (a repeated statement adds nothing) is per context: the same sentence in another supposition is stored again.
- Bare plurals: universal only as a statement's subject (the argument of the main verb or copula). Anywhere else (an object, or the complement under a non-copula verb) a bare plural is an indefinite. "Ben teaches math" stores a math thing; "Every nurse helps patients" is a rule that makes a patient for each nurse.
- Adverbs and prepositions: any predication whose first argument is an unused event, and whose second argument is an event, attaches as an atom on that event. "Every student studies hard" gives `hard(E)`.
- Negation under a copula: when the copula's clause is negated, the complement's restriction is negated too. A top-level `no` negates every head atom.
- Where: `_*_p_[ls]*` matches a locative or a state preposition by sense suffix.
- Coverage: compiles each sentence in an empty store with a real lookup, so a definite with no referent is refused with its count (0). The coverage script is not a dialogue, so definites never compile in it.
- The lemma scan (SPEC phase 1) covers the lemmas of `tests/sentences.txt`, as the spec says. The extra and round files are not scanned.
- Parser senses: "Jo writes letters." reads `write_v_to` and "Every pilot flies a plane." reads `fly_v_to`. These are the parser's sense choices, and the reading choice rule does not rank senses. Left as parsed. Open.
- Numbers ("two", "four", "three") are out of scope in SPEC.md and stay refused as `card`.
- Main clause through negation: `neg` sits at the top of the sentence and points at the clause it negates, so the main clause is that clause too. Before this, the subject of a negated statement was not seen as the subject, and "Dogs do not bark." stored one dog and lost the universal.
- Negated indefinite or bare noun: "Kim does not like fish." and "Kim does not own a dog." mean there is no fish Kim likes, which is the same as: every fish is one Kim does not like. In the store that is a negative rule, `not like(_, kim, Y) :- fish(Y)`, and no fish is created. The wide-scope reading ("some fish Kim does not like") is not stored: it is never what these sentences are used to say, and the parser does not distinguish the two scopes. This applies to an indefinite or bare noun that is not the subject and not a copula complement. A subject indefinite under negation ("A dog does not bark.") keeps its wide scope: some dog does not bark.
- `every` under negation ("Every dog does not bark.") is scope-ambiguous between all-not and not-all, and the store can hold only the first. Refused `SCOPE_AMBIGUOUS`. "No X" is not affected: it has one reading.
- Reading tie-break: after predicate overlap with the store and before the parser's order, prefer the reading that swallows fewer words (`_swallowed` in compile.py). A word is swallowed by a reading when most of the readings that compile give it a predication, from the parser's character spans, and this one gives it none. "Kim does not like fish." has a first reading in which `fish` is the verb and "like" has no predication; two of the three readings that compile span "like". Auxiliaries such as "does" are spanned by few readings, so leaving them out costs nothing. Two simpler measures were tried and dropped. Fewer unexpressed arguments broke "Where does Sam work?". Fewest unspanned stretches broke "Kim does not like Sandy.", by preferring a reading in which "does" is the main verb. This adds a step to the spec's tie-break and never overrides overlap.
- Consumption check: a reading compiles only if every predication is consumed. A `neg` must end up on at least one atom, and every variable a quantifier binds must appear in an atom, or be a constant, or be a copula complement merged into its subject. Otherwise `Refusal("UNCONSUMED", ...)`.
- A question whose wanted variable is in no positive body atom ("Who is Kim?", where the wh restriction `person` is abstract and gives no atom) is refused `UNCONSTRAINED_WANTED` by compile. The engine cannot enumerate a variable that nothing constrains.
- Negated question ("Does Pingu not fly?", "Does Kim not like fish?"): refused `NEGATED_QUESTION`. The engine reads a negated body atom as negation as failure, which is right in a rule body. In a question it answered Yes from the mere absence of a fact, against the spec's "absence is Unknown", and a question with no positive atom crashed. Answering by flipping Yes and No would be exact for a ground question only. A question must also have at least one positive atom.
- A rule whose restriction gives no atom is refused `EMPTY_RULE_BODY`. It arises when the grammar reads a capitalised bare plural ("Fish do not fly.", "Every robin is a bird." reading 2) as a name: the quantifier then ranges over one constant and the body is empty, and the engine cannot run it.
- A refusal ends the reading search when it says the store cannot hold the parser's preferred meaning (`MALFORMED` lists the refusals that mean the reading is not a sensible analysis, and these are skipped). Without this, "Nobody flies." was stored as a fact about a thing named Nobody, and "Which dog does not bark?" was answered from a reading where `dog` is a verb. This changes the spec's "among those that are not refusals": only readings ranked above the first such refusal compete. "Fish do not fly." still works: its name reading is malformed, not unsupported.
- Coordination: a conjunction predication (part of speech `c`: and, or, but) is refused `COORDINATION`. It was stored as a fact joining two events that exist nowhere else, and "or" was stored as "and". The pieces of a conjunction are not stored separately: that would drop the connective.
- Tense and aspect: only present, and past on the main event, are stored (past as `tense(e, past)`). Future, perfect and progressive on any event, and past on a subordinate event, are refused `UNSUPPORTED_TENSE` or `UNSUPPORTED_ASPECT`. They were silently dropped, so "Kim will sing." stored `sing(kim)`, and a rule over "who owned a dog" applied to present owners.
- Universal question ("Is every dog a mammal?"): refused `UNIVERSAL_QUESTION`. The ask machinery makes every quantified variable existential, so it answered "is some dog a mammal". An exact answer needs a counterexample search, which is not built.
- Merge rewrites premises: when a moved fact has a twin and is deleted, `why` rows that listed it as a premise now list the twin. A proof must never name a fact that is gone.
- Drop restores the state: it also deletes the supposition's sentence rows that nothing refers to, and `Mind` puts back each rule's `ran` round as it was when the supposition began.
- SPEC2 phase 9.4: `lf.REFUSALS` is the one table that classifies every refusal code as `final` or `reading`. This replaces the words "among those that are not refusals" in SPEC.md's "Choosing a reading", and replaces the `MALFORMED` set in compile.py. A final refusal means the sentence was understood and the store cannot hold it; the search ends there. A reading refusal means this reading is unusable and the next is tried. A test checks that every code in the source is in the table and that every final code has its motivating sentence.
- SPEC2 phase 9.5, reading choice. The order of criteria, applied in `compile.choose` and nowhere else. This replaces SPEC.md's "Choosing a reading".
  0. Only eventive readings are candidates (a predicate other than the unknown-word fallback takes the sentence event).
  1. Refusals, in parser order. A reading refusal (see `lf.REFUSALS`) is skipped. A final refusal ends the search: if no reading compiled before it, the sentence is refused with it; otherwise only the readings before it compete. If every candidate is a reading refusal, the first candidate's refusal is returned.
  2. Store overlap: the reading with the most (predicate, arity) pairs already in the store.
  3. Swallowed words: the reading that leaves out the fewest words that most of the compiled readings span (character spans from the parser).
  4. Parser order.
- SPEC2 phase 9.6: negation is stratified (`engine.strata`). Each rule gets a stratum above every rule that can derive an atom it negates; strata run in order, each to fixpoint. A rule that would close a cycle through negation is refused when told, `NEGATION_CYCLE` (it was `UNSTRATIFIED`; the name comes from SPEC2). Semi-naive evaluation now asks for a body fact from the round the rule last ran in or later, since a rule in a high stratum may not run for several rounds. This replaces "after the first run of a rule, each run requires at least one body atom from the previous round" in SPEC.md.
- SPEC2 phase 9.7: a repeat is detected by printed logical form (sentence rows now keep `printed` and `ctx`), and replies `already told: "<earlier text>"`. In force means the earlier sentence still has a stored fact, rule or merge. A repeat now applies to rules and identities too. Names are compared as printed, so two names of one merged thing are not recognised as a repeat. This replaces comparison by text.
- SPEC2 phase 9.8: preposition senses. Every stored preposition in the pairs tried (ten statement and question pairs, in, on and at) was carried by some reading of its question, and the overlap score selected it, so the scoring needed no change. The widening exists for the case where no reading carries it: `ask.answer` retries with `_lemma_p_*` only when the exact question found nothing, and prints `(widened: _in_p_state matched as _in_p_loc)`. Prepositions only. Not fixed, found while testing: "Where is Bob?" after "Bob is in Paris." is Unknown, because the where-question's atom has two arguments and the stored copular fact three; and "Ivy sings in Turin." stores a rule about all ivy, because the parser reads the capitalised common noun as a bare mass noun.
- The repl is the one place that catches `Exception`: an internal error prints one line to stdout and a full traceback to stderr, and the session goes on.
- SPEC2 phase 10: `Describe(entity)` is the logical form of "Who is X?" and "What is X?" when X is a name or resolved definite and the wh word has only the grammar's abstract restriction. Either argument order of the copula. The description lists facts that mention the entity, and facts on an event the entity takes part in (so "lives in Oslo" belongs to Kim's description, though its fact names only the event and Oslo). Told facts first, then derived, each with its source. A name with no facts is Unknown. "Who is Kim?" no longer exercises `UNCONSTRAINED_WANTED`; "Who is who?" does.
- SPEC2 phase 11: a conditional is the grammar's part-of-speech-`x` predication with two clause arguments, the consequent first and the antecedent second (read from the fixtures). Its antecedent, with the restrictions of the quantifiers over its variables, is the rule body; the rest is the head. An indefinite in the antecedent is a variable. A conditional question, or a conditional under a universal, is refused `UNSUPPORTED_PREDICATE`. A negated clause in a rule body that introduces its own indefinite ("If Kim does not own a dog") is refused `NEGATED_INDEFINITE`: as a negated body atom beside the restriction it would mean "for some dog Kim does not own", not "no dog". A rule body with no positive atom is refused `UNSAFE_NEGATION`, since it would fire on ignorance alone. The grammar's `unknown` fallback is a reading refusal `FALLBACK_PARSE`, so it no longer ends the reading search.
- Each `Mind.hear` runs in one transaction. An engine error after a rule was stored used to leave the rule in the store and break every later run.
- Observed, not fixed: the first reading of "If Kim does not own a dog, Kim is tired." takes `tire` as a verb with a scopal argument and ends the search with `UNSUPPORTED_PREDICATE`, though a later reading is the sentence. This is the cost of making `UNSUPPORTED_PREDICATE` final.
- SPEC2 phase 12: negated questions. A question's atoms keep their polarity; the claim is matched against facts of that polarity per atom, the opposite against the other kind (`ask._polarities`), so Yes and No swap and Unknown and Conflict stay. `NEGATED_QUESTION` is gone. A negated question over a bare or indefinite noun ("Does Kim not like fish?") asks about every such thing, so it is `UNIVERSAL_QUESTION` until phase 18 answers those. "Who does not fly?" stays `UNCONSTRAINED_WANTED`. `Match` takes a polarity per atom. The phase 12 statement half was already built by the review and was only verified.
- SPEC2 phase 13: pronouns. The fixtures show `pron` with `pronoun_q`, and PERS, NUM and GEND on the variable. PERS 1 is the fixed thing `user`, PERS 2 is `tolk` (both entities exist in every store; a person named Tolk would be the same thing). "We" and a plural "you" are refused. A third-person pronoun is the most recent thing mentioned that agrees in number, from earlier in the same sentence (named things and resolved definites only) or from the `mention(sentence, position, entity, number)` table. Candidates are de-duplicated by thing, and if the two most recent agreeing things were mentioned in the same sentence the pronoun is `AMBIGUOUS_PRONOUN`; none at all is `NO_ANTECEDENT`. Every logical form carries its resolution as a `note`, printed before anything is stored: `it = tweety`. Mentions are recorded for stored statements, rules and identities; questions are not stored, so they leave none. A thing created by an indefinite is a mention. "Kim owns a dog. It barks." is therefore ambiguous, since there is no gender. Merged names are followed at read time. Spoken about, `user` is "you" and `tolk` is "I", with "are" and "am". The lemma scan's function-word list gained "i", which the grammar's `card` reading carries as an argument.
- SPEC2 phase 14: numbers. Digits and number words both give `card` with a digit string. In a statement a cardinal on an indefinite or bare plural makes that many distinct things (`_expand`), each with the noun's atoms, all sharing the verb's event: collective readings are ignored. A cardinal on a bare plural subject makes it an indefinite, so "Two cats sleep." makes two cats and no rule. In a question, "How many N ...?" is `Ask` with `count`, answered with the number of distinct known things; a yes-or-no question with a cardinal is `atleast`, and is Yes or Unknown, never No. Zero known things counts 0, which means none known. A cardinal in a rule, two numbers in one question, zero, "more than", "most" and fractions are refused. Found on the way: `_fresh_ids` could give two new things in one sentence the same id.
